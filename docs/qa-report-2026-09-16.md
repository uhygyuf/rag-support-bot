## A. Executive summary

**Verdict: CONDITIONAL RELEASE.**

The product works end-to-end and is demonstrable: ingestion → retrieval → grounded answer with a
citation → multi-turn memory → refusal + ticket on an unanswerable question. All three
end-to-end journeys passed against the **published production webhook** (HTTP 200) during this pass.

Conditions before it can be shown to a paying client / recorded for the gig:

1. **QA-05 (P2, open)** — the handoff writes a ticket but **notifies nobody**; the "a human will
   reply" promise needs an email or Telegram notification node.
2. **QA-12 (P2, open)** — the demo site is not served (open `site/index.html` from disk or serve it)
   and the workflow has to be **published** for the widget's URL to answer.
3. **QA-09 (P3)** — one documented acceptance probe ("cheapest espresso machine") will *not* trigger
   a handoff any more; the demo script should use a probe that is genuinely absent from the docs.

No P0 defects. Four P1 defects were found and **fixed and re-tested** in this pass (wrong widget
protocol, wrong embed URL, unusable Chat Trigger settings, unsaved model credential).

## F. Remaining risks, limitations, next steps

1. **Notification (P2, feature gap)** — implement email (SMTP + app password) or Telegram in the
   ticket sub-workflow; then re-run E2E-3 and assert a notification is received.
2. **Publish discipline (P2)** — the chat endpoint is only live while the workflow is published;
   the CLI cannot register a webhook into a running instance, so publish from the editor or restart
   after `n8n publish:workflow`.
3. **Agent vs forced retrieval (design risk)** — retrieval is now enforced by prompt + tool
   description, not by graph structure. Watch for a regression where the agent answers without
   calling `knowledge_base`; a cheap guard is an execution-post-check on whether the tool was used.
4. **Supabase free tier** — projects pause after ~7 days idle (documented in `design-v0.md`).
5. **No performance testing** — answers took ~500 ms–11 s wall clock in executions; acceptable for a
   demo, unmeasured under concurrency.
6. **Version control / CI (P3)** — initialise a repo and run the suite on every change before
   handing artifacts to a client.
7. **Demo script** — use only verified probes: US shipping, Ethiopia Guji price, Canada shipping
   follow-up, wholesale, payment methods (answerable) and "Are you hiring baristas?" (handoff).
